The shape

A modular monolith on Spring Boot 4.1 and Spring Modulith 2.1, Java 25. One jar runs four roles by Spring profile — api, worker, scheduler, flyway — over PostgreSQL, Redis and RabbitMQ, with an optional outbound path to Anthropic Claude that degrades to a deterministic stub.

Nine business modules live under modules/. They may not import one another: each declares its allowed dependencies in package-info.java, and only contracts and shared appear on those lists. ModularityTests fails the build on any violation.

How modules communicate

ChannelMechanismCount
Synchronous A module declares an interface in its own api/; another module's implementation is wired in at the composition root. 13 ports
Asynchronous @ApplicationModuleListener over events in contracts/events — transactional, persisted, retried. 10 events

The property that matters most for the future: all 34 adapters live in boot/app, never inside a module. Dependency inversion is already done, so extracting a module into a service replaces an adapter with an HTTP client and touches neither module.

Tenant isolation

Many organisations share one database, so a leak between two of them is the worst failure the system has. Two independent barriers: TenantAccessGuard at the application tier, and PostgreSQL row-level security at the data tier — if a query forgets WHERE tenant_id = ?, the database still stops it.

RlsTenantAspect issues SET LOCAL app.tenant_id on the connection, inside the transaction. That detail is the single largest constraint on any serverless plan.

Path to production

One workflow at the monorepo root, sequential and fail-fast: commit-lint → changes → backend → backend-it (check, SpotBugs, JaCoCo) → frontend → security and CodeQL → e2e.

On a push to main: multi-arch build → GHCR → Trivy → cosign and SBOM → pin sha-<commit> onto the deploy/jetson branch → ArgoCD syncs the k3s cluster on Jetson. CD never commands the cluster; it edits one tag line in git.

  • Do not delete the deploy/jetson branch — ArgoCD reads its manifests from there, and it carries commits that exist nowhere on main.
